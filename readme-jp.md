## 概要

1 枚の人物画像から高精度にポーズを推定して xyz 座標データや任意の角度からの骨格画像を生成します。xyz 座標データは Qwen Image 2.1 の VNCCS PoseStudio LoRA を使用したポーズ指定に用いることができます。骨格画像は各種生成 AI 向けの ControlNet の pose 画像として使用可能です。

ポーズ推定は次の手順で行っています。

- 人物画像から MiniMax H3 360 Orbit LoRA を用いて 360 度周回動画を作成
- 周回動画に含まれる複数の角度の画像を取り出し、各画像に対してポーズ推定（体部位の xy 座標推定）を実行
- 複数の角度から推定した xy 座標データから最小二乗法等を用いて z 座標を推定

360° 周回動画（静止した人物の周りをカメラが一周する動画）の生成には MiniMax H3 の「360 ORBIT」ワークフローを用いることを想定していますが、必ずしもこれを使用して動画を作る必要はありません。等速で回転する 360 度周回動画を生成可能であれば、他の生成 AI で生成した動画や、実写動画からでもポーズ推定は可能です。

## ComfyUI カスタムノード

以下は、本リポジトリに含まれる ComfyUI カスタムノードです。

- **360-Orbit ポーズ推定**（360-Orbit Pose Estimation）: 動画（またはキーポイント）→ XYZ ポーズ JSON と、OpenPose 風の骨格画像。
- **360-Orbit XYZ ポーズエディタ**（360-Orbit XYZ Pose Editor）: XYZ ポーズを読み込み、直し、回し、保存するマネキンエディタ。
- **HM Qwen2.1 自由ポーズ XYZ (beta)**（HM Qwen2.1 Free Pose XYZ (beta)）: Fisher の Qwen Image 2.1 自由ポーズのノードで、エディタに XYZ ポーズファイルの読み込みを加えたもの。

表示は英語・日本語・中国語に対応しています（ComfyUI の言語設定に従います）。

## 入力動画について

入力動画は以下の要件をすべて満たす必要があります。いずれかが満たされていないと、ポーズ推定の精度が下がります。

- 1 人の人物を水平方向に回転させて 360 度方向から連続的に撮影した映像であること
- 5 秒の動画であること
- アスペクト比が 1:1 であること
- 各フレーム間の人物の回転角度が一定であること
- 最初と最後のフレームの人物のポーズが一致していること

以下、精度を高める工夫について記します。

- 背景を単色にすること: 人物の服装、髪の色、肌の色と異なる色の背景が望ましいです。
- 頭が画像の上方向にある動画にすること: 寝ているポーズの場合は、頭が上になるように回転させてからポーズ推定を行い、そのあとでポーズエディタで姿勢を回転させて寝たポーズに戻してください。
- 動画全てにわたって、人物の全身が映っていること: 手や足などが画面の外に出るフレームがある場合は推定精度が低下します。また人物の前に机などの遮蔽物がある場合や、人物が道具（作業道具、バットなどのスポーツ用具、楽器、バッグなど）を身に着けていたり、背負ったり持ったりしていると、推定精度が下がります。
- どの角度からでもポーズがよくわかる服装であること: マント、フード、裾の広いスカート、鎧、兜など、手、足、頭が大きく隠れる服装をしているとポーズ推定の精度が低下します。

実写以外の人物画像（例えばアニメのキャラ、デフォルメされたキャラクタ）は、ポーズ推定がうまくいかないことがあります。ポーズ推定の精度は SDPose の性能に依存します。

MiniMax H3 360 Orbit LoRA を使用して動画を作成するときは、入力画像を以下のようにしてください。

- 1人の人物だけが映っている
- アスペクト比が 1:1 である
- 背景が単色である
- 頭が画面の上方向にある

## ノード（カテゴリ `360-Orbit`）

### 360-Orbit ポーズ推定

前提: 人物は静止していて、カメラは人物の周りを、垂直な軸まわりに、一定の速さで回ります。選んだフレームの先頭は、1 周の始まりです（最後のフレームで 1 周が閉じます）。全フレームにわたって、関節の位置を、カメラ角度の正弦波にあてはめて、X・Y・Z を求めます（弱透視のモデル）。

**入力**: どれか 1 つを使います（優先順位は `keypoints` → `images` → `video`。どれもつながっていないとエラーです）。

| 入力 | 説明 |
|---|---|
| `images` | 周回動画の IMAGE バッチ |
| `video` | VIDEO（Create Video / Load Video など） |
| `keypoints` | 任意の推定器が出した、全フレームの POSE_KEYPOINT（ピクセル座標、0〜1 の正規化座標のどちらも可） |

**パラメータ**

| パラメータ | 既定値 | 説明 |
|---|---|---|
| `ckpt_name` | `sdpose_wholebody_fp16.safetensors` | SDPose のモデル（checkpoints フォルダ）。 |
| `batch_size` | 1 | SDPose で 1 回に処理するフレーム数。GPU メモリ不足を避けるため、小さくします。 |
| `frame_count` | 24 | 推定に使うフレーム数。1 周を等間隔に分けて選びます。 |
| `direction` | `auto` | 上から見たカメラの回る向き: `ccw`、`cw`、`auto`。`auto` は、鼻が首の前、膝が腰と足首を結ぶ線の前にくる向きを選びます。向きが逆だと前後が反転します。 |
| `start_angle` | 0 | 最初のフレームのカメラの方位角（度）。0 のとき、最初のフレームは人物の正面を見ています。 |
| `score_threshold` | 0.3 | これより低いスコアの関節は、検出できなかったものとして扱います。 |
| `min_valid_ratio` | 2/3 | 検出できた関節の割合がこの値以下のフレームは、使いません。 |
| `save_name` | `orbit_pose/pose-data` | 出力フォルダからの相対パスで指定する保存先（サブフォルダ可、出力フォルダの外には出られません）。6 桁の番号が付きます: `pose-data_000001.json`、次は `_000002`、…（名前ごとに数え、上書きしません）。 |
| `save_file` | オン | XYZ JSON をファイルに保存します。 |
| `pose_rotation` | 0 | 推定したポーズを、0 / 90 / 180 / 270° 回します（最初のフレームから見て反時計回り、骨盤が中心）。人物が動画の中で実際に横になっているときだけ使います。エディタで横になったポーズを使いたいだけなら、エディタの「画面内の回転」を使います。 |

**出力**

| 出力 | 説明 |
|---|---|
| `pose_xyz_json` | XYZ ポーズ JSON（形式は後述）。 |
| `images` | 補正したポーズを OpenPose 風に描いた骨格画像。推定に使ったフレームごとに 1 枚、入力と同じサイズ、黒背景です。動画合成ノードにつなぐと、骨格の動画になります。回転は反映しません。 |
| `rotated_images` | `pose_rotation` を反映した同じ画像（0 のときは `images` と同じ）。 |

**知っておくこと**

- 検出できた関節が少なすぎても、エラーにはなりません。標準の立ちポーズ（`meta.estimated` が `false`、理由は `meta.error`）と真っ黒な画像を出し、ノードに「ESTIMATION FAILED」と表示します。`score_threshold` や `min_valid_ratio` を下げると、推定できることがよくあります。入力が未接続、モデルがないなどの設定の誤りは、従来どおりエラーです。
- 回転したあとの胴体が立っていない（首が骨盤より、ほぼ上にない）ときは、ノードに警告が出て、`meta.upright` が `false` になります。エディタの読み込みは立った人物を前提にしているため、そのようなポーズは、前後が反転して見えることがあります。
- 選ばれた向きは、ノードの表示と `meta.direction_used` に出ます。

### 360-Orbit XYZ ポーズエディタ

**XYZ ポーズエディタを開く**ボタンで、マネキンのエディタを開きます。**ノードに適用**で、編集したポーズがノードに入ります。

- **出力**: `xyz_json` のみ。エディタで適用していれば編集後のポーズ、していなければ、接続した `xyz_json` 入力をそのまま出します（どちらもなければエラー）。
- **入力**: `xyz_json`（省略可）。接続した推定ノードを一度実行したあと、エディタで読み込めます。

### HM Qwen2.1 自由ポーズ XYZ (beta) – `HMQwenFreePoseXYZ`

Fisher の `FisherQwenFreePose`（Qwen Image 2.1、1 人）に、エディタでの XYZ ポーズの読み込みを加えたものです。入力・出力・エンコードは同じです: `clip`、`vae`、`reference_image`、`width`、`height`、`reference_resolution`、`extra_prompt`、`pose_json` → `positive`、`negative`、`latent`、`actual_prompt`、`mannequin_pose_image`。マネキンの画像が image1、人物の写真が image2、プロンプトは `Draw character from image2` に `extra_prompt` を足したものです（VNCCS_QI2_PoseStudio LoRA の決まり）。

- XYZ の入力端子はありません。エディタで XYZ ファイルを読み込みます。マネキン画像は、読み込んだあとに**ノードに適用**したときに作られます（適用しないで実行するとエラーです。Fisher のノードと同じ）。
- XYZ ポーズエディタの機能に加えて、このノードのエディタには、補足プロンプトの欄と、人物画像のプレビューがあります。
- 入っていないもの: Fisher のエディタにある OpenPose 画像のギャラリー（内蔵の `pose-images/` の骨格画像と、ユーザのライブラリ）と、その画像から 3D を作る処理。骨格画像は配布しません。必要な場合は、使う人が自分の責任で、Fisher のノード（ComfyUI-Fisher-Pose）を使ってください。
- Fisher のコードには依存しません（ComfyUI 本体の `TextEncodeQwenImage21` を直接使います）。マイポーズは Fisher と同じフォルダに保存されるので、どちらのエディタで保存したポーズも、もう一方で読めます。

## エディタ

XYZ ポーズエディタと Qwen ノードで共通です。

- **XYZ の読み込み**: `output/orbit_pose/` のファイルの一覧（サブフォルダの移動ができます。`orbit_pose` より上には行けません）、「ファイルを開く…」、そして（XYZ ポーズエディタのみ）接続したノードの出力。
- **前後反転**: 全身、上半身、左右の腕と脚（全体 / 先の側）。反転するたびに、XYZ のデータからポーズを取り込み直すので、手動で編集した関節は置き換わります（編集がある場合は確認が出ます）。
- **画面内の回転**: 0° / 90° / 180° / 270° のボタンとスライダー（反時計回り）。ポーズは立った状態で取り込み、そのあとマネキン全体を回します。四つん這いのような、横になったポーズは、こうして作ります。回転は、ノードに渡す画像とマイポーズに反映されます。保存・ダウンロードした XYZ ファイルは、立った状態のままです。前後反転をしても回転は保たれ、別のファイルを読み込むと 0° に戻ります。
- **保存**: 「XYZ JSON を保存」（`output/orbit_pose/` の下の、いま開いているフォルダに保存）、「ダウンロード…」、マイポーズ（`user/default/fisher_pose/poses/` に保存）。
- **警告**: 読み込みや前後反転で、ノードに適用も保存もされていない編集が失われるときは、確認が出ます。読み込んだポーズが、推定に失敗した標準の立ちポーズであるとき、または立っていないときは、お知らせが出ます。
- 体型、比例、手、関節の回転は、Fisher の自由ポーズエディタと同じように編集できます。

## XYZ ポーズ JSON（`orbit-pose-xyz`）

```json
{ "kind": "orbit-pose-xyz", "version": 1, "units": "m", "up": "y",
  "joints": { "pelvis": [0, 0.95, 0], "neck": [x, y, z], "head": [x, y, z],
              "left_shoulder": [..], "left_elbow": [..], "left_wrist": [..],
              "right_shoulder": [..], "right_elbow": [..], "right_wrist": [..],
              "left_hip": [..], "left_knee": [..], "left_ankle": [..],
              "right_hip": [..], "right_knee": [..], "right_ankle": [..] },
  "confidence": { }, "meta": { } }
```

15 関節、単位はメートルです。Y が上、+Z が人物の正面、+X が人物の左です。骨盤は (0, 0.95, 0)、首から骨盤までの長さは 0.6 です。`head` は、推定したファイルでは鼻、エディタで保存したファイルでは頭のボーンです。`meta` には設定と結果が入ります（`direction_used`、`pose_rotation`、`estimated`、`upright` など）。

## セキュリティ上の注意

このノードのエディタは、ComfyUI のサーバーに、次のルート（`/orbit360/*`）を追加します。

- `output/orbit_pose/` 以下の XYZ ファイルの、一覧・読み込み・保存
- マイポーズ（`user/default/fisher_pose/poses/`）の、一覧・読み込み・保存・削除

これらのルートには、ComfyUI 本体の `/view` や `/upload` と同じく、認証がありません。ComfyUI を `--listen` などでネットワーク（インターネットや共有の LAN）に公開すると、そのネットワークの他の端末から、これらのフォルダのファイルを読み書きできてしまいます。公開するときは、ファイアウォールやリバースプロキシの認証などで、アクセスを制限してください。

- 読み書きできるのは、上のフォルダの中の JSON ファイルだけです（`..` や絶対パスは拒否し、フォルダの外には出られません）。
- ノード A の `save_name` で書き出せるのは、出力フォルダの中だけで、既存のファイルは上書きしません。
- このリポジトリのコードは、ネットワークへのアクセスや、ComfyUI のフォルダの外へのファイルアクセスを、行いません（モデルの読み込みは、ComfyUI 本体の設定のとおりです）。
